Capstone · 2024 — 2025

Hack Slash

A player-versus-player mobile collectible card game that models cybersecurity threats through analytics-driven card design. I served as game developer, DevOps, and game designer — building mechanics in Godot (GDScript), storing live match state in Firebase Realtime Database, and keeping team builds consistent.

Minimax AI. Matches are turn-based, so the opponent cannot just pick a random card. Minimax looks ahead at possible moves for both sides and assumes each player will choose the strongest option — maximizing its own score while minimizing yours.

Offline / async matchmaking. You do not need another player online. Minimax fills that slot as the opponent, and its difficulty scales with your winrate and rank points — a higher rank means a harder match — so the game stays balanced instead of feeling too easy or unfair.

Descriptive

Tracks player win rates so matchmaking can pair decks of similar strength.

Predictive

Estimates a new deck’s likely win rate from historical results of each card.

Prescriptive

Highlights the most used, most effective, and highest-win-rate cards to build with.

RESTful APIs. The live game talks to backend services over HTTP. Firebase Realtime Database is the main REST layer (GET, PUT, PATCH, DELETE) for profiles, decks, matchmaking, leaderboard, store, achievements, and card analytics. Brevo’s REST API sends registration verification emails. Auth uses Firebase Identity Toolkit plus Google OAuth for sign-in and token refresh — no real-money payments.

Product · Ongoing

LSN Employee Management System

Internal HR and payroll platform for LSN Engineering Pte. Ltd. — covering employee lifecycle, daily time entry with OT, leave, training, dormitory assignment, payroll Excel/PDF payslips, client billing, and foreign-worker levy compilation.

Dual-company architecture: LSN Engineering and Chang Sheng Contractors share one ASP.NET Core codebase with separate PostgreSQL databases, branding, and session-based role security (site worker, office, admin). Excel via ClosedXML; payslip PDFs via Playwright.

Internal API. There is no public REST layer. Interactive screens call the same Razor Page with a handler query string (?handler=Name) that returns JSON or files — time entry, employees, payroll, billing, levy, and auth — so the UI and back-end stay in one ASP.NET pipeline.
